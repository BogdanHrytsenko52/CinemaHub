# CinemaHub

CinemaHub — REST API для одного кінотеатру з кількома залами. На цьому етапі
реалізовано керування жанрами, фільмами, залами, місцями й сеансами. Дані
зберігаються у SQLite через Django ORM.

Схема бази даних з попереднього етапу доступна у [database.png](database.png).
Моделі `User` і `Booking`, а також пов'язані маршрути, залишаються частиною
майбутньої роботи та зараз не реалізовані.

## Технології та сумісність

- Python 3.12
- Django 6.0.9
- Django REST Framework 3.18.3
- django-cors-headers 4.9.0
- SQLite

Версії зафіксовані в `requirements.txt`. Django 6.0, DRF 3.18.3 і
django-cors-headers 4.9.0 підтримують Python 3.12; django-cors-headers 4.9.0
також заявляє підтримку Django 6.0. Версію Django обрано 6.0.9 замість
початкової 6.1.x саме для задокументованої сумісності з CORS-пакетом.

## Як запустити проєкт

У PowerShell із кореня репозиторію:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

API буде доступне за адресою `http://127.0.0.1:8000/api/`.

Перевірки:

```powershell
python manage.py check
python manage.py test
```

## Демонстраційні дані

Щоб додати п'ять фільмів різних жанрів для показу frontend, виконайте:

    python manage.py seed_demo

Команду можна запускати повторно: вона створює відсутні жанри та оновлює фільми
за назвою без дублювання записів.

## Поточна специфікація API

Усі запити та відповіді використовують JSON. Базова адреса в прикладах:
`http://127.0.0.1:8000`.

### Жанри

- `GET /api/genres/` — список; `POST /api/genres/` — створення.
- `GET /api/genres/{id}/` — один об'єкт; `PATCH` — часткове редагування;
  `DELETE` — видалення.

```json
{"name": "Фантастика"}
```

### Фільми

- `GET /api/movies/`, `POST /api/movies/`
- `GET /api/movies/{id}/`, `PATCH /api/movies/{id}/`, `DELETE /api/movies/{id}/`

Список підтримує `search`, `genre_id` і `ordering`. Допустимі значення
`ordering`: `title`, `-title`, `rating`, `-rating`.

```json
{
  "title": "Interstellar",
  "description": "Фантастичний фільм про космічну подорож",
  "genre_id": 1,
  "duration": 169,
  "rating": "8.7",
  "age_rating": "12+"
}
```

Відповідь списку містить `id`, `title`, `genre_id`, `duration`, `rating`.
Детальна відповідь також містить `description` і `age_rating`.

### Зали та місця

- `GET /api/halls/`, `POST /api/halls/`
- `GET /api/halls/{id}/`, `PATCH /api/halls/{id}/`, `DELETE /api/halls/{id}/`
- `GET /api/halls/{id}/seats/` — місця вибраного залу.
- `GET /api/seats/`, `POST /api/seats/`
- `GET /api/seats/{id}/`, `PATCH /api/seats/{id}/`, `DELETE /api/seats/{id}/`

```json
{"hall_id": 1, "row": 1, "number": 1}
```

Окремий ресурс `/api/seats/` додано для повного CRUD; попередній маршрут
перегляду місць залу збережено.

### Сеанси

- `GET /api/sessions/`, `POST /api/sessions/`
- `GET /api/sessions/{id}/`, `PATCH /api/sessions/{id}/`, `DELETE /api/sessions/{id}/`
- `GET /api/sessions/{id}/seats/`

Для списку доступні `movie_id` і `date` у форматі `YYYY-MM-DD`:
`/api/sessions/?movie_id=1&date=2026-10-20`.

```json
{
  "movie_id": 1,
  "hall_id": 1,
  "start_time": "2026-10-20T18:00:00Z",
  "price": "200.00"
}
```

`GET /api/sessions/{id}/seats/` повертає `id`, `row`, `number` і
`is_available`. Поки бронювань немає, усі місця доступні; після реалізації
`Booking` це поле обчислюватиметься за активними бронюваннями.

## Статуси, помилки та бізнес-правила

- `200 OK` — успішний перегляд або редагування; `201 Created` — створення;
  `204 No Content` — видалення.
- `400 Bad Request` — невалідні дані, параметри або пов'язаний ідентифікатор.
- `404 Not Found` — об'єкт не знайдено.
- `409 Conflict` — операція суперечить наявним даним.

Усі очікувані помилки повертаються в одному форматі:

```json
{
  "error": {
    "code": "bad_request",
    "message": "Request data is invalid.",
    "details": {"duration": ["Ensure this value is greater than or equal to 1."]}
  }
}
```

Правила предметної області:

- назви жанрів і залів унікальні;
- `duration` від 1 до 600 хвилин, `rating` від 0.0 до 10.0, `price` додатний;
- ряд і номер місця додатні; комбінація `(hall_id, row, number)` унікальна;
- сеанси не можуть перетинатися в одному залі; інтервал визначає тривалість
  фільму;
- жанр не видаляється, коли має фільми; фільм — коли має сеанси; зал — коли має
  місця або сеанси. Ці спроби повертають `409 Conflict`.

## CORS і Postman

Frontend має зберігатися в окремому репозиторії. Бекенд дозволяє запити лише з
`http://localhost:5173` через `CORS_ALLOWED_ORIGINS`; глобальний доступ через
`CORS_ALLOW_ALL_ORIGINS` не використовується.

Колекція [postman/CinemaHub.postman_collection.json](postman/CinemaHub.postman_collection.json)
має формат Collection v2.1 та використовує змінну `{{base_url}}` зі значенням
`http://127.0.0.1:8000`.

## Архівна документація попереднього етапу

Наступний розділ збережено як початковий дизайн. Реалізованою специфікацією є
розділ «Поточна специфікація API» вище; авторизація, профіль і бронювання тут
описані лише як майбутній функціонал.

CinemaHub -- це сайт кінотеатру, на якому можна переглядати фільми, дізнаватися розклад сеансів і бронювати місця.

Я вирішив зробити сайт для одного кінотеатру з декількома залами. Ідея полягає в тому, 
щоб людина могла вибрати фільм, подивитися, коли він іде, та забронювати місце, не звертаючись до каси.
На головній сторінці буде список фільмів. Їх можна буде шукати за назвою, фільтрувати за жанром і сортувати за 
рейтингом або назвою. На сторінці фільму буде його опис, тривалість, жанр, вікове обмеження та доступні сеанси.

Також планую зробити:
- Перегляд розкладу на вибрану дату.
- Перегляд вільних і зайнятих місць.
- Реєстрацію та вхід користувачів.
- Бронювання місць.
- Особистий кабінет з історією бронювань.
- Можливість скасувати бронювання.
- Редагування даних профілю.

Фільми, жанри, зали та сеанси адміністратор зможе додавати й редагувати через стандартну адміністративну панель Django.

## REST API

Для обміну даними між сайтом і сервером планую використовувати REST API. Дані передаватимуться у форматі JSON.

Основні методи:
- `GET` -- отримання даних.
- `POST` -- створення запису.
- `PATCH` -- зміна даних.
- `DELETE` -- видалення або скасування.

У прикладах `{id}` -- це ID конкретного запису.

### 1. Фільми

**GET /api/movies/**

Повертає список фільмів.

Параметри:
- `search`  -- пошук за назвою.
- `genre_id` -- фільтр за жанром.
- `ordering` -- сортування (`title`, `-title`, `rating`, `-rating`).

Приклад: `/api/movies/?genre_id=1&ordering=-rating`

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "title": "Interstellar",
    "genre_id": 1,
    "duration": 169,
    "rating": 8.7
  }
]
```

**GET /api/movies/{id}/**

Повертає детальну інформацію про фільм.

Відповідь: `200 OK`

```json
{
  "id": 1,
  "title": "Interstellar",
  "description": "Фантастичний фільм про космічну подорож",
  "genre_id": 1,
  "duration": 169,
  "rating": 8.7,
  "age_rating": "12+"
}
```

### 2. Жанри

**GET /api/genres/**

Повертає список жанрів.

Відповідь: `200 OK`

```json
[
  {"id": 1, "name": "Фантастика"},
  {"id": 2, "name": "Комедія"},
  {"id": 3, "name": "Драма"}
]
```

**GET /api/genres/{id}/**

Повертає інформацію про конкретний жанр.

Відповідь: `200 OK`

```json
{
  "id": 1,
  "name": "Фантастика"
}
```

### 3. Зали та місця

**GET /api/halls/**

Повертає список залів кінотеатру.

Відповідь: `200 OK`

```json
[
  {"id": 1, "name": "Зал 1"},
  {"id": 2, "name": "Зал 2"}
]
```

**GET /api/halls/{id}/seats/**

Повертає місця конкретного залу. Їхня зайнятість залежить від сеансу, тому тут показується лише розташування.

Відповідь: `200 OK`

```json
[
  {"id": 1, "row": 1, "number": 1},
  {"id": 2, "row": 1, "number": 2}
]
```

### 4. Сеанси

**GET /api/sessions/**

Повертає список сеансів.

Параметри:
- `movie_id` — сеанси конкретного фільму.
- `date` — сеанси на вибрану дату.

Приклад: `/api/sessions/?movie_id=1&date=2026-10-20`

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "movie_id": 1,
    "hall_id": 1,
    "start_time": "2026-10-20T18:00:00+03:00",
    "price": 200
  }
]
```

**GET /api/sessions/{id}/**

Повертає інформацію про конкретний сеанс.

Відповідь: `200 OK`

```json
{
  "id": 1,
  "movie_id": 1,
  "hall_id": 1,
  "start_time": "2026-10-20T18:00:00+03:00",
  "price": 200
}
```

**GET /api/sessions/{id}/seats/**

Повертає місця залу та показує, які з них вільні на конкретний сеанс.

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "row": 1,
    "number": 1,
    "is_available": true
  },
  {
    "id": 2,
    "row": 1,
    "number": 2,
    "is_available": false
  }
]
```

### 5. Користувачі

**POST /api/auth/register/**

Реєструє нового користувача.

Запит:

```json
{
  "username": "user123",
  "email": "user@example.com",
  "password": "example123"
}
```

Відповідь: `201 Created`

```json
{
  "id": 1,
  "username": "user123",
  "email": "user@example.com"
}
```

**POST /api/auth/login/**

Вхід в обліковий запис.

Запит:

```json
{
  "username": "user123",
  "password": "example123"
}
```

Відповідь: `200 OK`

```json
{
  "message": "Login successful"
}
```

**POST /api/auth/logout/**

Вихід з облікового запису. Тіло запиту відсутнє.

Відповідь: `200 OK`

```json
{
  "message": "Logout successful"
}
```

**GET /api/users/me/**

Повертає інформацію про поточного користувача.

Відповідь: `200 OK`

```json
{
  "id": 1,
  "username": "user123",
  "email": "user@example.com"
}
```

**PATCH /api/users/me/**

Змінює дані профілю.

Запит:

```json
{
  "email": "new@example.com"
}
```

Відповідь: `200 OK`

```json
{
  "id": 1,
  "username": "user123",
  "email": "new@example.com"
}
```

Для авторизації планую використати стандартні сесії Django. Паролі не будуть повертатися у відповідях API.

### 6. Бронювання

Для спрощення одне бронювання буде відповідати одному місцю на одному сеансі. 
Якщо користувачу потрібно декілька місць, він зможе забронювати їх окремо.

**GET /api/bookings/**

Повертає історію бронювань поточного користувача.

Відповідь: `200 OK`

```json
[
  {
    "id": 1,
    "session_id": 1,
    "seat_id": 2,
    "price": 200,
    "status": "confirmed"
  }
]
```

**POST /api/bookings/**

Створює бронювання. Користувач вибирає сеанс і місце.

Запит:

```json
{
  "session_id": 1,
  "seat_id": 2
}
```

Відповідь: `201 Created`

```json
{
  "id": 1,
  "session_id": 1,
  "seat_id": 2,
  "price": 200,
  "status": "confirmed"
}
```

Якщо місце вже зайняте, сервер повертає `409 Conflict`:

```json
{
  "error": "Seat is already booked"
}
```

**DELETE /api/bookings/{id}/**

Скасовує бронювання користувача. Запис залишається в історії, але місце знову стає доступним.

Тіло запиту відсутнє.

Відповідь: `200 OK`

```json
{
  "id": 1,
  "status": "cancelled"
}
```


### Обробка помилок

Якщо користувач запитує неіснуючий фільм або сеанс, сервер повертає `404 Not Found`. Якщо вибране місце вже заброньоване, 
повертається `409 Conflict`. Інші помилки планую обробляти під час реалізації API.

## База даних

Для зберігання даних планую використовувати SQLite. На початку достатньо семи основних таблиць.

### Зв'язки між таблицями

- Один жанр може мати багато фільмів, але кожен фільм має один основний жанр.
- Один фільм може мати багато сеансів.
- Один зал має багато місць.
- Один зал може використовуватися для багатьох сеансів.
- Один користувач може створювати багато бронювань.
- Кожне бронювання пов'язане з користувачем, сеансом і конкретним місцем.

Зайнятість місця визначатиметься за активними бронюваннями на відповідний сеанс, а не зберігатиметься окремо в таблиці місць.
